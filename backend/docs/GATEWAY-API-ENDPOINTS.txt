1. AUTHENTICATION

POST /auth/login  
Roles: anyone

Request:
{
  "email": "email0@test.org",
  "password": "pass0"
}


Success (200):
{
  "user": {
    "userId": "user0",
    "username": "name0",
    "email": "email0@test.org",
    "role": "USER"
  },
  "message": "ok"
}


JWT is stored in a cookie.  
JWT token payload:

{
  "sub": "user0",
  "username": "name0",
  "email": "email0@test.org",
  "role": "USER", (USER | SUPPORT | ENGINEER | ADMIN)
  "iat": 1700000000,
  "exp": 1700003600
}


Errors:
401 - Wrong email or password  
429 - Too many login attempts (5 max per 15 minutes)?

POST /auth/logout  
Role: any logged-in role

Request: none

Success (200):
{
  "message": "ok"
}

GET /auth/verify
Roles: any logged-in role

Request: none (token in cookie)

Success (200):
{
  "valid": true,
  "user": {
    "userId": "user0",
    "username": "name0",
    "role": "USER"
  },
  "expiresIn": 1800  // seconds until expiration
}

Errors:
401 - Token expired or invalid
{
  "error": "Token expired",
  "valid": false
}

4.3 PATCH /incidents/:id
Roles:
- ENGINEER
- ADMIN

Description:
Update incident fields: status, urgency, and/or category.
Only provided fields are updated.

ENGINEER limitations:
- Can set status only to IN_PROGRESS or RESOLVED
- Cannot set status to CLOSED
- Can only increase urgency

ADMIN:
- Can update all fields without restrictions

REQUEST BODY:
{
  "status": "IN_PROGRESS" | "RESOLVED" | "CLOSED",
  "urgency": "low" | "medium" | "high" | "critical",
  "category": "network" | "database" | "security" | "other"
}

SUCCESS RESPONSE (200 OK):
{
  "incidentId": "inc0",
  "incidentNumber": "INC-0",
  "status": "RESOLVED",
  "urgency": "critical",
  "category": "network",
  "priority": "P1",
  "updatedBy": "engineer0",
  "updatedAt": "2025-01-15T15:30:00Z"
}

ERROR RESPONSES:

400 Bad Request
Invalid status value
Resolution notes are required when status = RESOLVED
Cannot decrease urgency. Current: CRITICAL, Requested: HIGH
Invalid category

403 Forbidden
{
  "error": "Engineers can only change status to IN_PROGRESS or RESOLVED"
}

404 Not Found
Incident not found
